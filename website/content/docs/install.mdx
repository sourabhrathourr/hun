You can have Hun running in a couple of minutes. You need a license key, the app, and nothing else.

## Requirements

- A Mac with Apple silicon.
- macOS 15 or later.
- [Docker Desktop](https://www.docker.com/products/docker-desktop/), only if your projects run services with `docker` or `docker compose`.
- Git, only for the branch switcher.

## Install Hun

<Steps>

<Step>
### Buy a license

Hun is a one-time purchase of $9. One key works on up to 3 Macs, and updates are included. Buy it on the [pricing page](/pricing). Your license key appears after checkout and in your purchase email.
</Step>

<Step>
### Download the app

Download the latest [`hun-macos-arm64.dmg`](https://github.com/sourabhrathourr/hun/releases/latest/download/hun-macos-arm64.dmg) from GitHub releases.
</Step>

<Step>
### Move it to Applications

Open the disk image and drag **hun** into **Applications**. Then open Hun from Applications.

Hun has to run from `/Applications` to put the `hun` command on your PATH.
</Step>

<Step>
### Paste your license key

Hun opens on **Activate Hun**. Paste the key from your purchase email into **License key** and click **Activate Hun**.

The Hun icon appears in your menu bar, and the main window opens.
</Step>

</Steps>

## The `hun` command

When Hun starts from `/Applications`, it links the `hun` command that ships inside the app into the first of these folders it can write to:

1. `/usr/local/bin`
2. `/opt/homebrew/bin`
3. `~/.local/bin` (created if needed)

Hun keeps that link pointing at the current app after every update. If one of those folders already has a `hun` that didn't come from the app, Hun leaves it alone.

Open a new terminal and check:

```bash
which hun
hun version
```

<Callout title="hun: command not found?">
If Hun linked into `~/.local/bin`, that folder may not be on your PATH. You can always run the copy inside the app: `/Applications/hun.app/Contents/Resources/hun`. See [troubleshooting](/docs/troubleshooting#hun-command-not-found).
</Callout>
