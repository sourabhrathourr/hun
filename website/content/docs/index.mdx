Hun is a Mac app that runs your project's dev servers, workers and databases from a `.hun.yml` file in the project. It starts them in dependency order on free ports, keeps their logs, and shows what's running from your menu bar. The `hun` command and your coding agents control the same services, so everything ends up in one place.

## How Hun works

Hun has three parts:

- **The app.** A menu bar item and a main window. It shows your projects and their services, and sends your clicks to the daemon.
- **The daemon.** A background process that starts and stops your services, picks their ports and keeps their logs. Closing the window doesn't stop anything; the daemon keeps your services running.
- **The `hun` CLI.** The app comes with it and puts it on your PATH. Every command talks to the same daemon, and starts it if it isn't running.

The daemon keeps its files in `~/.hun`:

| Path | What it holds |
| --- | --- |
| `~/.hun/daemon.sock` | The socket the app and the CLI use to talk to the daemon |
| `~/.hun/state.json` | Registered projects, what's running and each project's last profile |
| `~/.hun/logs/` | Service logs, one file per service |
| `~/.hun/config.yml` | Optional global settings, see [global config](/docs/hun-yml#global-config) |

If the daemon restarts, it starts the projects that were running before.
